# Schedules, destinations, approvals, and dispatch

Recurring work has four distinct concerns: **when to run, where an output may go, who must approve it, and whether the provider actually delivered it**.

## Schedules

Current schedules are evaluated in UTC. A scheduled slot is queued with a deterministic identity so retries do not create duplicate runs.

Before queueing, Piggy Banker evaluates readiness. A blocked or unevaluated required check prevents the run. Advisory setup warnings can remain visible without being silently converted into required data.

## Destinations

Destinations are server-bound from workspace defaults or deployment overrides. Generated text cannot redirect a report to an arbitrary channel.

A deployment should make the intended channel, workspace, and output format obvious before activation.

## Manual test first

A manual test is a dry run:

- it reads current permitted evidence,
- produces an in-app artifact,
- creates no external delivery,
- creates no approval request, and
- lets an operator inspect output and provenance.

Use the queued live path only after the dry-run artifact is acceptable.

## External action lifecycle

```text
proposal → human decision → queued dispatch → provider result
```

- The proposal contains the exact normalized payload and destination.
- A different eligible person reviews it; the proposer cannot approve their own external action.
- Approval queues dispatch. It does not mean delivery already happened.
- The worker sends the approved payload through the configured provider connection.
- Delivery identifiers, failures, and retry history remain visible.

If the payload changes or expires, Piggy Banker requires a new approval. Retrying a failed delivery does not silently mutate what was approved.

## Current Slack posture

Scheduled report generation with human-approved Slack delivery is supported by the current control model. Fully unattended production Slack posting is not currently enabled as a public workflow.

<Warning>
  Do not treat an enabled schedule as permission to send. Schedule eligibility, action approval, and dispatch state remain independent.
</Warning>
