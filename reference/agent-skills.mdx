# Skills: reusable agent instructions

A Skill tells an agent **how** to perform a task, which approved source categories it may use, and what the output should look like. It does not grant access or permissions.

## Examples

Skills can support work such as:

- financial analysis,
- executive brief writing,
- KPI explanation,
- Slack drafting,
- anomaly review,
- cash forecasting,
- reconciliation, and
- close-package preparation.

Current categories organize Skills as Analysis, Reporting, Monitoring, Reconciliation, and Comms.

## Built-in and custom Skills

- **Built-in Skills** are maintained by the platform.
- **Custom Skills** are client-specific instruction artifacts with a mutable draft and immutable published versions.

A deployment can follow the latest published version or remain pinned to a specific version. Every run records the exact Skill snapshot and content hash it used.

## A useful Skill contains

1. **Purpose** — the outcome and intended audience.
2. **Approved evidence** — source categories the workflow should consult.
3. **Procedure** — ordered reasoning and calculation steps.
4. **Controls** — required checks, exclusions, and escalation conditions.
5. **Output contract** — structure, tone, units, period labels, and citations.
6. **Review criteria** — what a human should verify.

## Skills do not expand authority

A Skill cannot:

- grant a tool,
- grant tenant or client access,
- choose an unconfigured destination,
- override a deployment policy,
- bypass human approval,
- write to an accounting ledger, or
- turn a manual test into an external delivery.

Runtime capabilities come from the server-owned tool and source catalog plus the signed-in person's and deployment's permissions.

## Publishing discipline

Test a draft against representative client evidence. Publish a new immutable version for a material change. Pin critical workflows until the new version has been reviewed, then deliberately move deployments forward.
