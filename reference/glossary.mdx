# Piggy Banker glossary

## Product structure

**Firm**<br />The account and billing tenant that contains a CFO team and its managed clients.

**Client workspace**<br />The isolated operating and data scope for one business.

**Client portal**<br />A separate authenticated shell for client collaborators; not the internal workspace with hidden navigation.

**Overview**<br />The client destination for tasks, alerts, and agent activity.

**Context**<br />Durable Company, Money, and Strategy facts that help interpret finance data. Context is not canonical finance data.

**Page**<br />A free-form composition of metric-backed finance blocks for a decision or audience.

**Templates / Playbooks**<br />The firm-level library for reusable layouts, workflow blueprints, and finance operating procedures.

**Lil Piggy**<br />A private, client-scoped notepad and grounded finance companion.

## Data and models

**Connection**<br />A client-scoped authorization and sync relationship with a provider.

**Linked account**<br />One independently tracked provider company, tenant, item, or account relationship.

**Source data**<br />Provider-derived finance domains made available after sync.

**Canonical finance data**<br />Provider-neutral records normalized for the client while retaining source lineage.

**Domain owner**<br />The one selected ready source used to answer a finance domain.

**Lineage**<br />Metadata that connects a value to its client, provider, linked account, source object, period, and sync.

**Freshness**<br />How current a dataset is relative to its expected cadence and as-of time.

**Measure**<br />A numeric finance result, such as Revenue or Ending cash.

**Dimension**<br />A categorical attribute used to group or filter measures, such as department, class, location, customer, or entity.

**Metric definition**<br />The reusable name, meaning, type, formula, dependencies, source references, and format for a measure.

**Metric series**<br />Periodized or point-in-time values associated with a metric definition.

**System reference**<br />A read-only value derived from connected books or a plan.

**Reusable input**<br />A directly entered scalar saved for reuse by multiple metrics.

**Forecast assumption**<br />A model- or scenario-specific planning driver.

**Formula**<br />A bounded expression over approved, client-scoped references.

**Unavailable**<br />A required value cannot be resolved. It is materially different from a measured zero.

## Agents and controls

**Agent template**<br />A reusable workflow blueprint.

**Revision**<br />An immutable published version of a template or Skill.

**Deployment**<br />A revision configured for one client with schedules, destinations, Context, Skills, policies, and overrides.

**Run**<br />One execution with snapshotted configuration, evidence, tool activity, results, and events.

**Skill**<br />Reusable versioned instructions and output expectations for an agent. A Skill does not grant permissions.

**Workspace default**<br />A firm or client default inherited by a deployment unless explicitly overridden.

**Artifact**<br />A reviewable output saved by a run or Lil Piggy session.

**Proposal**<br />The exact normalized external action payload submitted for a human decision.

**Approval**<br />A human decision that permits dispatch of the approved payload. Approval is not delivery.

**Dispatch**<br />The queued attempt to send an approved payload through a provider.

**Destination**<br />A server-bound external target, such as a configured Slack channel.

**Dry run**<br />A manual test that creates an in-app artifact without external delivery or approval work.

## Availability labels

**Available now**<br />Backed by the current product contract and implementation, although individual workspace rollout can vary.

**Coming soon**<br />Part of the decided final product model but not fully shipped.

**Implemented-dark**<br />A technical seam exists but is not a public or self-service product.

**Planned**<br />Directional; not a commitment to current availability.
