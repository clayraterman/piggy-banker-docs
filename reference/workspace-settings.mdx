# Workspace settings and access

Administration is split between the firm account and each client. This keeps portfolio-level controls separate from a client's finance model.

## Firm-level administration

Firm owners are responsible for:

- billing and subscription ownership,
- firm members,
- the client portfolio,
- shared operating defaults, and
- firm-level Templates / Playbooks as that library rolls out.

Firm operators can work across client operations within their granted access without becoming billing owners.

## Client-level administration

Client configuration includes:

- client collaborators and roles,
- business Context,
- provider Connections,
- source-data readiness,
- metrics and finance-model configuration,
- agent deployments,
- client destinations, and
- client-specific overrides.

## Defaults and overrides

A workspace default can provide consistent configuration such as reporting style, Context pack, Slack channel, Notion destination, or approval policy. An agent deployment either inherits that default or records an explicit override.

The resolved value should be inspectable on every run. “Default changed later” must not erase what a historical run used.

## Access boundaries

- Firm scope does not collapse client data into one tenant.
- Client roles apply to one business.
- The authenticated portal is a separate shell.
- A read permission does not grant write, approval, or external-delivery authority.
- A proposer cannot approve their own outbound action.

## During rollout

Settings may be distributed across current product surfaces while the final firm and client navigation converges. Use the controls actually visible in your workspace; these docs avoid inventing a universal settings screen.
