Create a saved metric when a measure should have one definition that Pages and agents can reuse.

## Open Metrics

Inside the client workspace, open **Pages** and select **Metrics**. The management window includes **Metrics**, **Source data**, and **Dimensions**. You can open it before creating your first Page.

<Steps>
  <Step title="Choose the source of the value">
    Use **New metric** or an add-row control. Create from available source data, enter a manual input, or build a formula from saved metrics. Connected accounting lines stay tied to their source; a manually entered assumption is not a ledger actual.
  </Step>
  <Step title="Name and describe it">
    Use a name that identifies the measure and a description explaining exclusions or special treatment. Confirm its client and entity scope.
  </Step>
  <Step title="Set time and presentation behavior">
    Choose the number format and rollup. Revenue is a period flow; cash is an ending balance. Confirm actual and forecast periods, the selected scenario, and the visible month window.
  </Step>
  <Step title="Review dependencies and dimensions">
    Check the linked source or formula references. Use dimensions only where the underlying rows carry the relevant attributes. An aggregate statement cannot provide a department breakdown it never contained.
  </Step>
  <Step title="Reconcile and reload">
    Compare a known month with the source. Check missing values and, for ratios, a zero denominator. Wait for the save, reopen Metrics, and confirm the definition and value remain correct.
  </Step>
  <Step title="Use it on a Page">
    Add a metric-backed block to the Page and choose the saved metric. Keep the same period and scenario for your first comparison. Later, each block can present the shared metric in its own appropriate view.
  </Step>
</Steps>

## Example: operating expense ratio

Define operating expense divided by revenue for the same entity, month, basis, and currency. Set percentage formatting. Decide how unavailable revenue and a zero denominator should be presented; neither justifies inventing a result.

## Before you rely on it

Confirm the name matches the calculation, every dependency is understandable, and manual inputs remain distinguishable from actuals. Changing a shared definition can affect other Pages and agents.
