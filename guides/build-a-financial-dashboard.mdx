# Build a financial Page

A useful Page starts with a decision, not a pile of charts.

<Note>
  **Coming soon:** This guide describes the accepted Pages workflow. Exact click paths and the final block catalog will be added when the Pages editor ships.
</Note>

## 1. Define the audience and decision

Examples:

- a weekly CEO liquidity review,
- a monthly board P&L,
- a department budget review,
- a 13-week cash forecast, or
- a hiring affordability view.

Write the date cadence and the action the reader should be able to take.

## 2. Select trustworthy metrics

Choose the smallest set that explains the decision. For each metric, confirm:

- source and readiness,
- time behavior,
- entity and currency,
- formula and dependencies,
- relevant dimensions, and
- whether the value is actual, input, or assumption.

## 3. Give the Page a hierarchy

A practical order is:

1. decision summary,
2. primary outcome measures,
3. drivers and variances,
4. detailed table or statement,
5. assumptions and data caveats, and
6. follow-up actions.

## 4. Configure blocks locally

Bind each block to saved metrics, then choose the Page-specific date range, comparison, visible dimensions, formatting, and order. Do not create duplicate metrics simply to change a chart style.

## 5. Make provenance visible

Show the period and as-of date. Distinguish connected actuals, observed balances, manual inputs, and forecast assumptions. If a dependency is stale or unavailable, surface that state.

## 6. Review before reuse

Reconcile at least one period to the source books. Check formulas at boundary cases. Review the Page with its intended audience, then save the structure as a template when the same decision recurs across clients.

## A good first Page

Start with a compact CFO overview:

- cash and liquidity,
- revenue and gross margin,
- operating spend,
- runway or forecast ending cash,
- major variances,
- source freshness, and
- current actions.

More blocks do not make the model more trustworthy. Clear definitions and visible lineage do.
