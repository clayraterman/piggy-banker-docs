# Pages: compose living finance views

Pages are the free-form, Notion-style home for financial models, dashboards, and metric management. A Page composes shared finance primitives into a view for a specific decision or audience.

<Note>
  **Coming soon:** The final Pages route and free-form editor are a decided product contract, not a fully shipped destination in the current app. Existing reporting, forecasting, planning, and dashboard routes are compatibility internals during the transition.
</Note>

## What a Page contains

A Page can compose metric-backed blocks such as:

- key-number summaries,
- financial statements,
- tables,
- charts,
- variance views,
- narrative and operating notes, and
- model-specific inputs or assumptions where appropriate.

The exact block catalog will be documented as each block ships.

## Bind, do not copy

A Page block should reference a metric definition or series. It should not copy the metric's current value into page content.

That separation creates two useful layers:

| Shared finance meaning | Page-local presentation |
| --- | --- |
| Name and definition | Date window |
| Formula and dependencies | Comparison period |
| Unit and value type | Chart or table style |
| Source and lineage | Sort, order, and visible dimensions |
| Recorded series | Narrative framing |

When a metric definition is corrected, every Page that binds it can use the corrected meaning without duplicating logic.

## Pages and metrics

Metrics management belongs inside Pages because models and dashboards are where operators discover what they need. The metric remains a reusable client-level object even when it is first created while editing a Page.

## Pages and agents

The target flow lets an agent use the same metrics and Context that support a Page. Today, agent tools read canonical finance data and reporting primitives; they do not yet consume a rendered Page object or send a Page snapshot.

## Page templates

A Page template should preserve structure, block configuration, and semantic metric bindings without copying one client's finance data into another. See [Templates and Playbooks](/concepts/playbooks).
