# External agent access with MCP and WebMCP

Piggy Banker's long-term direction includes permissioned ways for external agents to read the same governed client data used inside the product.

<Warning>
  **Internal proof only:** There is no public, self-service, or named private-preview MCP/WebMCP product today. Do not paste an endpoint into Claude, ChatGPT, or another client based on an old or generated guide.
</Warning>

## Intended access model

External access must preserve the same rules as the product:

- explicit company grants,
- client-scoped roles and scopes,
- opaque external references,
- deny-by-default authorization,
- audit history, and
- bounded data returned through approved tools.

## Current internal seam

The implemented-dark external seam is read-only. It is designed around company discovery, finance reads, Context-package reads, artifact listing, and workflow status.

It does **not** expose:

- write tools,
- journal-entry or ledger mutation,
- agent execution,
- approval decisions,
- external dispatch,
- webhooks, or
- subscriptions.

WebMCP export remains a product direction rather than a shipped public interface.

## Why the boundary matters

A convenient agent connection cannot be allowed to bypass client isolation, source lineage, approvals, or destination policy. Public access will require productized authentication, grant management, audit, support, and revocation—not just an endpoint.

## What to use now

Use Lil Piggy and Agents inside Piggy Banker for grounded client work. There is no supported external-agent setup to follow today.
